# 作品上传审核

## 状态模型

作品审核状态与作品可见性相互独立：

- `PENDING`：等待审核，不允许通过公开接口展示。
- `APPROVED`：审核通过，再根据作品自身的 `PUBLIC`、`PRIVATE` 等可见性状态决定展示范围。
- `REJECTED`：审核未通过，不允许展示，并保存拒绝原因供作者在内容管理中查看。

新上传作品统一进入 `PENDING`。已通过或审核中的作品修改标题、正文、封面或作品图片后，会进入或刷新 `PENDING`。审核未通过的作品可以继续编辑，但保存修改时保持 `REJECTED` 并保留拒绝原因；作者确认修改完成并点击“再次提审”后，才原子切换为 `PENDING`，同时清空旧拒绝原因、审核人和审核时间。只修改公开或私有状态不会重复送审。

## 作品归属与署名

作品归属字段必须按以下语义使用，不能互相替代：

- `author`：平台内当前归属账号 UUID。自创作品保存上传作者；未认领的收录作品保存“蔚蓝收录助手”；认领通过后改为认领用户。
- `uploader`：执行收录操作的平台用户 UUID，只用于收录作品。
- `author_nickname`：站外原作者署名，只用于收录作品；原作者可能没有平台账号。

因此，未认领收录作品的管理详情应分别展示“暂归属：蔚蓝收录助手”“收录者：平台收录用户”“原作者：站外署名”。`author_nickname` 不参与平台归属解析。

## 展示约束

公开作品列表、作品详情、图片资源、点赞、评论以及喜欢列表都要求作品同时满足：

1. 作品可见性为 `PUBLIC`；
2. 审核状态为 `APPROVED`。

作者通过登录后的“我的作品”接口查看自己的 `PENDING` 和 `REJECTED` 作品。审核通过前，即使作者选择了私有状态，也不会进入正常展示链路。

## 权限约束

审核接口要求管理员权限值包含 `SEC_MAINTAINER` 位。判断方式是严格的二进制位判断，而不是比较权限数值大小，因此权限值更高但未包含该位的管理员仍不能审核作品。

## 接口

- `POST /api/work/manage/reviews`：按审核状态、关键词和分页查询审核队列。
- `POST /api/work/manage/review`：通过或拒绝待审核作品；拒绝时必须填写不超过 500 字的原因。
- `POST /api/work/works_by_me`：作者内容管理列表，可通过 `review_status` 查询审核中或审核未通过的作品。
- `POST /api/work/review/resubmit`：仅作品作者或收录者可将自己的 `REJECTED` 作品再次提交为 `PENDING`。

审核通过和拒绝均只写入审核记录与管理员操作日志，不发送电子邮件。

## 数据迁移

Flyway 迁移 `V7__add_work_review.sql` 新建 `work_review` 表。为保持上线前已有作品的展示行为，迁移时将历史作品回填为 `APPROVED`；迁移后的新作品默认创建为 `PENDING`。
