## 一、系统概述

**蔚蓝收录馆 (Barc)** 是一个二次元学园/部团/学生/作品管理系统，主要用于管理二次元角色（学生）及其创作（作品）。

### 核心定位
- 收录二次元学园（School）、部团（Club）、学生（Student）的信息
- 管理学生上传的作品（Work），支持分类、评论、认领等功能
- 提供用户注册登录、消息留言、反馈建议等服务

#### 用户端 API 接口（公开只读，全部 `@IgnoreAuth`）
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/category/all | 获取全部分类（树形） |

| GET | /api/category/all_not_graded | 获取全部分类（扁平，当前无调用方） |

#### 管理端「作品管理 → 作品分类」接口（`MANAGER` + `SEC_MAINTAINER` 1匹配）
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/category/manage/list | 分类树（含每个分类的直接作品数与子分类数） |
| POST | /api/category/manage/create | 新增分类（`id` 手填，`parent_id` 为空即顶级分类） |
| PUT | /api/category/manage/{id} | 修改名称 / 排序 / 父分类（移动父分类会级联修正子树层级并做防环校验） |
| PUT | /api/category/manage/{id}/sort?direction=up\|down | 同级上移 / 下移 |
| DELETE | /api/category/manage/{id} | 删除（有子分类或有作品关联时拒绝） |

#### 约束
- 分类 `id` 为手填语义化主键（`^[a-z0-9_]{1,50}$`），**创建后不可修改**
  （`work_category.category_id` 外键没有 `ON UPDATE CASCADE`）；
- 名称 ≤ 20 字（列宽 `varchar(20)`），同一父级下不允许重名，不同父级允许同名；
- `level` 由后端按 `parent_id` 派生，前端不可传入；
- 删除受约束：外键为 `ON DELETE CASCADE`，有子分类或有作品关联时会被拒绝，避免连坐删除；
- 分类的启用/停用（`is_enabled`）与图标（`icon`）当前在用户端零消费，本次未做；
- 用户端只展示与选择**顶级分类**；子分类用于归档与后续扩展
  （详见 `docs/superpowers/specs/2026-09-19-work-category-management-design.md`）。

### 3.11 背景图模块 (Background)

管理端支持为各页面（登录/注册、首页、加入我们、意见反馈、留言板、学生详情）上传/启用/排序背景图。

#### 页面背景字段
| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 主键 |
| module | String | 所属模块 code（sign/home/join/feedback/messageboard/student） |
| object_key | String | COS 对象 key |
| filename | String | 文件名 |
| sort_order | int | 排序 |
| enabled | boolean | 是否启用 |
| time_period | String | 时段标签：`day`/`eventing`/`night`，NULL 表示任意时段 |
| festival | String | 绑定的节日 ID（对应 `festival` 表），NULL 表示无节日通用图 |
| created_by | String | 创建人 UUID |
| created_at / updated_at / deleted_at | Date | 创建/更新/删除时间 |

#### 公开接口
- `GET /api/background/all`（无需登录）：返回所有启用背景图，按 `module` 分组，每项为 `{ url, time_period, festival }`（url 已解析为 COS 签名 URL）。

#### 首页背景图「按时间 + 节日」切换逻辑（用户端）
首页背景图（`HomeBgComp.vue`）从启用图池中按当前场景选一张（每次访问随机换一张，不自动轮播）：
1. **节日**：拉取 `GET /api/festival/all` 得到启用中的节日，按当前日期判定所属节日，优先取绑定该节日的图；节日期内无节日图则用无节日通用图。非节日期只用 `festival=NULL` 的图。
2. **时段**：在选定池内优先取匹配当前时段的图（白天 6-17 点、傍晚 17-19 点、夜晚 0-6 与 19-24 点），含未标注时段的通用图；无匹配则退回整个池。
3. **兜底**：管理端无任何启用图时，回退到写死的时段/新年图片。

其它模块（sign/join/feedback/messageboard）仅从该模块启用图中随机取一张。

### 3.12 节日模块 (Festival)

管理端「系统管理 → 节日管理」，仅**馆长**（权限位 `ADVANCED_ADMINISTRATOR`，1匹配鉴权）可访问。

#### 节日字段
| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 主键 |
| name | String | 节日名称（不可重复） |
| start_month / start_day | int | 起始月日 |
| end_month / end_day | int | 结束月日 |
| start_index / end_index | int | 派生统一索引（月 * 32 + 日），用于比较与排序 |
| enabled | boolean | 是否启用；false 表示已关闭 |
| bound_backgrounds | int | 绑定该节日的背景图数量（列表展示用，非数据库列） |
| created_by | String | 创建人 UUID |
| created_at / updated_at / deleted_at | Date | 创建/更新/删除时间 |

#### 日期录入方式与持久化
- **月份式**：只填起始月与结束月（如新年 12 月 → 次年 2 月），落库自动展开为该月第一天至该月最后一天；
- **日期式**：精确填写某月某日到某月某日；
- 两种方式持久化的本质都是「某月某日 → 某月某日」；`start_month > end_month` 表示该区间**跨年环绕**（如新年 12-01 → 02-28）。

#### 管理端接口（1匹配/馆长）
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/festival/admin/list` | 节日列表（含已关闭），附带绑定背景图数量 |
| POST | `/api/festival/admin/create` | 新增节日 |
| PUT | `/api/festival/admin/{id}` | 修改节日（名称 + 日期区间） |
| PUT | `/api/festival/admin/{id}/enabled` | 关闭 / 启用节日 |
| DELETE | `/api/festival/admin/{id}` | 删除节日（自动解绑背景图） |
| GET | `/api/festival/options` | 管理端：全部节日（含已关闭），供背景图下拉与筛选用 |
| GET | `/api/festival/all` | 公开：启用中的节日（无需登录） |

#### 迁移说明
- **V10**：建 `festival` 表，并把存量 `background_image.festival = 'newyear'` 归一为「新年」节日的固定 ID
  `0000000000000000000000000000f001`；该迁移写成「先 DELETE 再 INSERT」的幂等形式，重跑不会主键冲突。
- **V11**：订正「新年」的统一索引。V10 种子曾按「月 * 31 + 日」手算写成 `386 / 478`（478 已越出合法上界 415），
  导致该行被当成非跨年区间、新年季判定失效；V11 修正为 `385 / 93`（12-01 → 02-29）。
- ⚠️ 已执行过的迁移脚本**不可就地修改**（会破坏 Flyway checksum 校验导致启动失败），后续订正一律新增版本。

#### 业务规则
1. **不可重叠重合**：新增/修改时按「逐日枚举」精确比对（而非区间端点数值比较，因为统一索引在相邻月之间留有空隙，端点比较会把毫无交集的区间误判为重叠），与任何既有节日——**含已关闭的节日，其区间仍被占用**——重叠都会被拒绝，并返回冲突的节日名称；
2. **关闭**：仅置 `enabled=false`，保留数据与背景图绑定，用户端不再判定为该节日；重新启用即恢复；
3. **删除**：同一事务内先把绑定该节日的背景图 `festival` 置为 NULL（自动划归「无节日」通用图），再逻辑删除节日，避免用户端取图链路指向不存在的节日；接口返回 `unboundBackgrounds` 告知受影响图片数量；
4. **跨年区间**：`start_month > end_month` 表示区间跨年环绕（如新年 12-01 → 02-28），重叠判定与用户端归属判定都按「绕年一圈」处理。

## 五、认证与权限

### JWT 认证
- Token 存储在请求头 `Authorization: Token <token>`
- 登录成功返回 Token
- 修改操作需要携带 Token

### 身份枚举 (UserIdentityEnum)

| 枚举值 | 中文名 | 说明 |
|--------|--------|------|
| `USER` | 用户 | 普通用户身份 |
| `MANAGER` | 管理者 | 管理员身份 |

### 权限系统（位运算）

系统采用**位运算**实现权限控制，通过 `user_archive.identity` 和 `user_archive.permission` 字段组合实现细粒度权限管理。

#### 普通用户权限 (identity = USER)

| 常量 | 十进制值 | 二进制 | 说明 |
|------|---------|--------|------|
| `USER` | 1 | 0000 0001 | 会员：浏览、留言、点赞、收藏、反馈 |
| `UPPER` | 2 | 0000 0010 | 收录员：发布、收录、处置作品 |
| `CREATOR` | 4 | 0000 0100 | 创作者：与收录员相同 |

#### 管理者权限 (identity = MANAGER)

| 常量 | 十进制值 | 二进制 | 说明 |
|------|---------|--------|------|
| `DISCIPLINARY_COMMITTEE` | 1 | 0000 0001 | 风纪委员：警告、公告、审批认领 |
| `FIR_MAINTAINER` | 2 | 0000 0010 | 一级管理员：处理评论/留言举报 |
| `SEC_MAINTAINER` | 4 | 0000 0100 | 二级管理员：处理作品举报 |
| `THI_MAINTAINER` | 8 | 0000 1000 | 三级管理员：处理用户举报 |
| `ADMINISTRATOR` | 16 | 0001 0000 | 副馆长：管理所有非馆长用户 |
| `ADVANCED_ADMINISTRATOR` | 32 | 0010 0000 | 馆长：超级管理员，管理全部 |

#### 权限对比工具 (ComparePermission)

```java
// 比较 basic >= target（权限值是否大于等于目标）
compare(int your, int target)

// 判断是否有某权限 (your & target) != 0
has(int your, int target)
```

#### 鉴权注解 (@RequireUserAndPermissionAnno)

```java
@RequireUserAndPermissionAnno({
    @RequireUserAndPermissionAnno.Check(
        identity = UserIdentityEnum.MANAGER,      // 身份要求
        targetPermission = PermissionConst.THI_MAINTAINER,  // 目标权限
        isSuchElseRequire = false                // 是否需要满足全部条件
    ),
    @RequireUserAndPermissionAnno.Check(uuidIndex = 1)  // UUID 参数位置
})
```

#### 管理端功能权限对照

| 管理功能 | 所需权限 |
|----------|----------|
| 学园/部团/学生管理 | `FIR_MAINTAINER` (2) |
| 作品审核/管理 | `SEC_MAINTAINER` (4) |
| 用户管理 | `THI_MAINTAINER` (8) |
| 管理员管理 | `ADMINISTRATOR` (16) |
| 全部权限 | `ADVANCED_ADMINISTRATOR` (32) |

## 六、存储策略

### 文件存储
- **腾讯云 COS**: 统一使用腾讯云 COS 对象存储
- **存储方式**: 私有桶 + 签名 URL
- **访问模式**: 通过后端生成临时签名 URL 访问，签名有效期有限

#### 签名 URL 流程
```
1. 前端请求后端上传文件
2. 后端上传文件到 COS 私有桶
3. 前端需要访问时，后端生成带签名的临时 URL
4. 前端通过签名 URL 访问文件
```

### 文件类型
- 用户头像
- 学生立绘/头像
- 作品图片
- 作品 Banner/封面
- 动态图片

## 九、注意事项（面向 AI 开发）

1. **ID 生成策略**：部分实体 ID 由后端自动生成（使用 UUID 或雪花算法），前端不应自增
2. **时间格式**：统一使用 ISO8601 格式
3. **多对多关系**：作品与分类通过中间表关联
4. **软删除考虑**：部分表使用外键级联删除，需注意数据一致性
5. **安全等级**：邮箱验证、手机绑定等会影响 safe_level
6. **文件上传**：需关注存储服务的可用性和配额
7. **评论嵌套**：仅支持一层回复（parent_id）
8. **分类树**：支持无限层级，但需注意前端渲染性能
