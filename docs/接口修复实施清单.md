## 最终契约与实施取舍

1. **公开读取和管理写入分开授权。** 匿名用户可搜索用户及访问公开主页；新增 `GET /user/query/search` 返回轻量白名单。旧用户搜索兼容委托同一服务，官方绑定和作者指派保留各自写权限。多 Check 为全部满足，同一身份的任一角色位使用单个按位或掩码。
2. **认领完整保留。** 用户可提交、分页查看进度和结案结果；风纪委员或二级管理员可查看/审核，撤销及指派继续要求二级管理员位。批准和拒绝均保留历史，重复待审申请受数据库约束。
3. **作者提审与管理员审计分开。** 两端复用编辑详情构造器。普通编辑仅接受内容字段；旧通用更新兼容委托对应命令。正文、图片和分类变化增加版本；审核携带 `expected_revision`。状态、归属、正文使用窄字段更新，恢复使用原可见性。
4. **账号安全操作使用 JSON。** 本地及 Naigos 登录、验证码申请、注册、改密、邮箱改绑已迁移双端；携带凭据的旧 GET 停用。邮箱改绑验证当前口令及新邮箱，改密验证绑定邮箱与专用场景。新密码用随机盐 PBKDF2-HMAC-SHA256、600000 次迭代，旧口令正常验证后条件升级。新外部账号默认禁用本地口令，历史自动默认口令不能用于本地登录或敏感确认。
5. **数据库只写对象 key。** 展示 DTO 分开原始 key 与签名 URL，基础资料表单不回写签名 URL。上传前独立登记补偿对象，绑定和 GC 共用对象锁；失败回滚引用，旧对象延迟回收并重新核对引用。GC 默认关闭，历史 MinIO URL 继续展示，历史文件仅登记退役清单。
6. **富文本在服务端及双端展示处净化。** 后端按 [jsoup 白名单](https://jsoup.org/cookbook/cleaning-html/safelist-sanitizer)处理新写入和历史读取；双端作品、公告和审核展示通过 [DOMPurify](https://github.com/cure53/DOMPurify)及排版白名单处理。允许安全排版和 HTTP(S) 图片，移除事件、脚本、SVG、iframe、危险 URL/CSS。历史数据库正文未被批量覆盖。
7. **错误与分页保持可迁移性。** J 响应保留 `code/msg/data`，文本错误在 msg/data 中同义；现有业务失败继续用非零 code，认证失效用 HTTP 401，绑定错误 400，数据库唯一键/关联冲突 409，限流 429。列表默认有界，分页容量最多 100；完整遍历使用分页入口，不依赖大 limit。旧数组响应保留形状和有界兼容包装。
8. **外部副作用按事务边界处理。** 邮件在业务事务内持久入队，提交后按租约投递，失败最多重试五次；验证码邮件有过期限制。数据库 DDL、实际对象清理、上游协议与上线操作不冒充本地单元测试可验证的内容。

## 数据库迁移与只读预检

- 空库由 `B13__empty_database_baseline.sql` 初始化，再执行 V14～V22；已有 Flyway 历史的库继续增量升级。V1～V13 未改动。采用 Flyway [Baseline migrations](https://documentation.red-gate.com/flyway/flyway-concepts/migrations/baseline-migrations) 机制，不把空库验证等同于存量库结构已确认。
- V14～V22 增加账号会话安全字段、邮件队列、存储登记、基础关系审计、动态 key、作品版本、认领历史和目录事务锁，并修正既有字段契约。V20 的待审唯一标记只依赖状态，兼容 MySQL 生成列与级联外键限制。
- V22 在字段变更前阻断未知作品状态及重复部团归属，不猜测业务含义、不清理历史行；分类关联数字主键转字符串保留原值。仍需维护者确认实际 MySQL 版本及结构漂移。
- [api-audit-preflight.sql](../BarcBackend/db/validation/api-audit-preflight.sql) 仅列出结构、未知状态、重复归属、学生学园不一致、图片 URL 污染记录编号及 GC 桶分布，不输出签名或凭据。**本轮未对现有业务库执行此脚本或迁移。**
